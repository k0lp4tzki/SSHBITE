Cold start of the 2,000-host subnet heatmap (assessment §1: < 2 s)
==================================================================

Method (evidence/p6/cold_start.py): for every block a fresh `sshbite synth --hosts 2000 --seed 42` DB and a fresh
`sshbite serve` process. "API" = urllib, login then GET /api/scans/1/heatmap?group_by=subnet four times.
"Browser" = Chromium 1280x800; time from navigation until canvas.cells is drawn (data-rendered), plus the page's
own "built in N ms" (performance.now() from the request to the drawn matrix), then three reloads.
Machine: this workspace (no Docker). check-12 saw 4,744 ms on its own instance; I could not reproduce that figure
here - the worst cold case on this machine was 0.98 s - so the numbers below show the effect of the fix, not
check-12's environment.

Cause
-----
1. Derivation on the first request / cold cache: the first heatmap request of a scan builds its ScanView
   (2,000 hosts, 18,969 edge rows with JSON flags, natural sort): ~140-170 ms here. Nothing built it earlier
   unless the Dashboard had already been opened.
2. No single flight: the heatmap page asks for the matrix and the ranking at the same moment. Both requests
   missed the cache and built the same ScanView in parallel threads under the GIL, so each took about twice
   as long (browser: heatmap 674 ms and ranking 764 ms instead of ~110 ms). On a slower or busier machine this
   doubles a several-times larger cost, which is consistent with 4.7 s.
   (No index was missing: every query of the view uses the scan_id index; EXPLAIN QUERY PLAN checked.)

Fix (sshbite/web/data.py Views, app.py, api.py list_scans)
---------------------------------------------------------
- single flight per scan: concurrent requests wait for one build;
- warm-up: a daemon thread builds the views of the two newest completed scans at server start and whenever
  the scan list is read (the UI reads it on every load), so a scan finished while the UI runs is warm too.
  A failed warm-up only logs a warning; the request path builds the view as before.
No change to the API, the data or the heatmap computation.
